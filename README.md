# Weather Mood

Πλατφόρμα για ξενοδοχεία και τουριστικές επιχειρήσεις που μετατρέπει την πρόγνωση καιρού σε προτάσεις εκδρομών.
Το MVP καλύπτει τα **Χανιά (Κρήτη)**.

> Παράδειγμα: αύριο φυσάει δυτικός 4 Bf με κύμα 1,2 m → τα Φαλάσαρνα (κοιτάνε δυτικά) απορρίπτονται,
> προτείνονται Κολυμπάρι, Μαράθι και η ανατολική πλευρά της Παλαιόχωρας, που είναι προστατευμένα.

## Πώς δουλεύει

1. **Δεδομένα**: [Open-Meteo](https://open-meteo.com): άνεμος/ριπές από 5 μοντέλα (ECMWF, ICON, GFS, Météo-France, UK Met Office),
   θερμοκρασία/αίσθηση/βροχή/UV, και θαλάσσια πρόγνωση (κύμα, swell, θερμοκρασία νερού).
2. **Ανάλυση** (`src/engine/analysis.ts`): διάμεσος άνεμος των μοντέλων και πόσο διαφωνούν. Για κάθε παραλία υπολογίζεται
   αν ο άνεμος φυσάει προς την ακτή ή από τη στεριά, και πόσο από το κύμα των ανοιχτών φτάνει στην ακτή. Προστίθενται τοπικά φαινόμενα, π.χ. οι ριπές από τα βουνά στα Σφακιά με βοριά.
3. **Κρίση ανά προφίλ** (`src/engine/scoring.ts`): κάθε ώρα ξεκινά από 100 και χάνει πόντους για κάθε πρόβλημα, με τους αριθμούς του.
   Επιλέγεται το καλύτερο χρονικό παράθυρο. Η βαθμολογία καιρού είναι ξεχωριστή από τη σειρά πρότασης, η οποία λαμβάνει υπόψη και απόσταση, προφίλ και «σπάνια ευκαιρία».
   **Σκληρά όρια** πάνω από τη βαθμολογία (`hardLimits`): παραλία/λίμνη με αίσθηση < 18° ή νερό < 18° → το πολύ «με επιφύλαξη»,
   < 15° ή < 16° → «αποφύγετε»· βροχή ≥ 60% ή ≥ 1 mm στο παράθυρο → «με επιφύλαξη», ≥ 80% ή ≥ 3 mm → «αποφύγετε» (σκάφος: το ίδιο για βροχή,
   μόνο «με επιφύλαξη» για κρύο)· φαράγγι με βροχή στη μέρα ≥ όριο σημείου (Σαμαριά 50%) ή ≥ 3 mm ή καταιγίδα → «αποφύγετε»
   (κίνδυνος απότομης πλημμύρας/κλεισίματος), 20 μονάδες κάτω από το όριο ή ≥ 1 mm → «με επιφύλαξη».
4. **Προτάσεις** (`src/engine/recommend.ts`): 3 κορυφαίες επιλογές από διαφορετικές περιοχές, εναλλακτικές, και τι να αποφύγει κανείς.

## Οθόνες

| Σελίδα | Για ποιον | Τι δείχνει |
|---|---|---|
| `index.html` | Ξενοδόχος / host / reception | Πλήρης ανάλυση: 5 μοντέλα, θάλασσα ανά ακτή, βαθμός ανά σημείο, εξήγηση, μήνυμα για επισκέπτες |
| `guest.html` | Επισκέπτης (QR στο δωμάτιο) | Σελίδα για κινητό σε 4 γλώσσες (EL/EN/DE/FR): «Ποιοι ταξιδεύετε;», 3 προτάσεις, «Τι να πάρετε», οδηγίες χάρτη |
| `guest.html#lobby` | Οθόνη reception | Προτάσεις για αύριο για οικογένειες, ζευγάρια και πεζοπόρους, γλώσσες που εναλλάσσονται, QR |
| `accuracy.html` | Υποψήφιοι πελάτες (ξενοδόχοι) | Δημόσια σελίδα ακρίβειας: πόσο πέφτουμε μέσα, με τα στοιχεία του νυχτερινού ελέγχου και τις ψήφοι επισκεπτών, EL/EN, ανανεώνεται μόνη της |
| `guest.html#reception` | Προσωπικό reception | Φόρμα 20 δευτερολέπτων: «ο επισκέπτης γύρισε και είπε…» (μέρος, 👍/👎, τι δεν πήγε καλά) |

| `guest.html#qr` | Reception | Εκτυπώσιμη κάρτα δωματίου με το QR |

Τα στοιχεία κάθε καταλύματος βρίσκονται στο `src/data/properties.json`: όνομα, θέση, χρώμα, λογότυπο, WhatsApp/email, **αγαπημένα σημεία**
(σήμα «Αγαπημένο του …» στις κάρτες) και **συμβουλές του ξενοδοχείου** (ταβέρνα, ενοικίαση αυτοκινήτου, εισιτήρια σκάφους, με σύνδεσμο ή τηλέφωνο)
που εμφανίζονται ως ενότητα «Από το …» στη σελίδα επισκέπτη. Επιλογή καταλύματος: `?p=<id>` στο URL ή variable `VITE_PROPERTY_ID`.
Το demo χρησιμοποιεί φανταστικό κατάλυμα.

### Πλάνο διαμονής («ποια μέρα για Σαμαριά;»)

Ο επισκέπτης δηλώνει μέχρι πότε μένει και η σελίδα μοιράζει τις μεγάλες εκδρομές (Μπάλος/Γραμβούσα, Ελαφονήσι, Φαλάσαρνα, φαράγγι,
Σφακιά/Λουτρό, Ακρωτήρι) στις μέρες της διαμονής: μία εκδρομή τη μέρα, πρώτα όσες έχουν λίγες καλές μέρες (`src/engine/stay.ts`).
Οι 3 πρώτες μέρες έχουν πλήρη πρόγνωση ανά σημείο· για τις μέρες 4–7 το snapshot κρατάει μια **7ήμερη πρόγνωση στα σημεία αναφοράς**
(βόρεια/δυτική/νότια ακτή, πόλη) και κάθε σημείο παίρνει τα δεδομένα της κοντινότερης ακτής (`proxyDataset` στο `src/engine/openmeteo.ts`).
Κάθε μέρα φέρει ένδειξη εμπιστοσύνης (σίγουρο / πιθανό / εκτίμηση) και το πλάνο ανανεώνεται κάθε βράδυ.

### Θάλασσα, ήλιος, UV

Η καρτέλα κάθε σημείου δείχνει θερμοκρασία νερού («δροσερό 22°»), δείκτη UV με συμβουλή σκιάς, και ώρα ηλιοβασιλέματος για τα σημεία
με ωραίο ηλιοβασίλεμα. Το πλαίσιο καιρού δείχνει την ώρα δύσης της μέρας.

### Εγκατάσταση στο κινητό και ειδοποιήσεις (PWA)

Η σελίδα επισκέπτη έχει manifest και service worker (`public/sw.js`): «Προσθήκη στην αρχική οθόνη», λειτουργία χωρίς σύνδεση με το
τελευταίο πλάνο, και **ειδοποιήσεις push** για το βραδινό μήνυμα και το πρωινό Plan B (δωρεάν, χωρίς WhatsApp Business).
Ο επισκέπτης πατάει «Ναι, ειδοποιήστε με»· η συνδρομή αποθηκεύεται στον πίνακα `push_subscriptions` (μόνο εισαγωγή με το δημόσιο κλειδί,
`supabase/migrations/0002_push_subscriptions.sql`) και τα Actions στέλνουν με [web-push](https://github.com/web-push-libs/web-push).
Ρύθμιση: `VITE_VAPID_PUBLIC_KEY` στο `.env` (δημόσιο), secret `VAPID_PRIVATE_KEY` και variable `VAPID_PUBLIC_KEY` στο repo, προαιρετικά
`VAPID_SUBJECT` (mailto:). Δημιουργία ζεύγους: `npx web-push generate-vapid-keys`.

Τα σημεία βρίσκονται στο `src/data/spots.ts`. **Είναι αρχική καταγραφή** (`verified: false`) και χρειάζονται επιτόπιο έλεγχο.

## Feedback επισκεπτών (το δεδομένο που δεν έχει κανείς άλλος)

Η σελίδα κινητού θυμάται τι προτείναμε και την επόμενη μέρα ρωτάει «Πήγατε; Πώς ήταν;» (👍 ή 👎 + κύμα/αέρας/κόσμος…).
Η reception καταχωρεί ό,τι της λένε οι επισκέπτες στο `guest.html#reception`. Κάθε ψήφος δένεται με την πρόγνωση που είχαμε δώσει
για εκείνο το μέρος και εκείνη τη μέρα.

- Αποθήκευση: Supabase (δωρεάν tier), πίνακες `feedback` και `visits`. Σχήμα: `supabase/migrations/0001_feedback_and_visits.sql`
  (τρέχει μία φορά στον SQL Editor του project). Το δημόσιο κλειδί στο `.env` μπορεί **μόνο να γράφει** (row-level security)·
  κανείς δεν διαβάζει ψήφους από τον browser. Χωρίς κλειδιά στο `.env` το feedback απλώς δεν εμφανίζεται.
- Το Action `.github/workflows/feedback.yml` τρέχει κάθε πρωί με το service key (secrets `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`):
  ενώνει τις ψήφους με την αρχειοθετημένη πρόγνωση (`data/feedback/rows.jsonl`), γράφει τα σύνολα για το dashboard
  (`public/data/feedback.json`, καρτέλα «Μέθοδος & πηγές» → «Τι είπαν οι επισκέπτες») και την αυτόματη διόρθωση κύματος
  (`public/data/calibration.json`).
- Διόρθωση κύματος (`src/engine/feedback.ts`): όταν ένα σημείο έχει ≥ 8 ψήφους με πρόγνωση και οι επισκέπτες βρίσκουν συστηματικά
  περισσότερο (ή λιγότερο) κύμα από όσο είπαμε, ο συντελεστής κύματός του αλλάζει 5% ανά ψήφο, με όριο ±30–40%. Αέρας και κόσμος
  δεν διορθώνονται αυτόματα.
- Μετράμε και ανώνυμα ανοίγματα σελίδας (κινητό/οθόνη, γλώσσα, προφίλ) για την αναφορά χρήσης προς το κατάλυμα. Χωρίς προσωπικά δεδομένα.

## Βραδινό μήνυμα και Plan B

- **18:40 Αθήνας** (`.github/workflows/evening.yml`): φρέσκια πρόγνωση, μετά το πρόγραμμα της επόμενης μέρας για κάθε προφίλ και το
  έτοιμο μήνυμα σε EL/EN/DE/FR (`public/data/evening.json`, αρχείο ανά μέρα στο `data/messages/`). Το ίδιο κείμενο βλέπει ο ξενοδόχος
  ζωντανά στην καρτέλα «Προτάσεις» → «Βραδινό μήνυμα», με κουμπιά Αντιγραφή / WhatsApp / Email.
- **05:50 Αθήνας** (`.github/workflows/morning-check.yml`): ξαναϋπολογίζει τη σημερινή μέρα με την πρωινή πρόγνωση και τη συγκρίνει με
  το βραδινό μήνυμα (`src/engine/planchange.ts`). Αν άλλαξε κάτι που νοιάζει τον επισκέπτη (πρόταση έγινε «αποφύγετε», ο άνεμος
  ανέβηκε ≥ 2 Bf, βροχή, κύμα), γράφει το `public/data/plan-b.json` και το dashboard δείχνει banner με το νέο μήνυμα.
- **Email στη reception** (προαιρετικό): με secrets `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `RECEPTION_EMAIL`
  τα δύο Actions στέλνουν τα κείμενα έτοιμα για προώθηση. Χωρίς SMTP απλώς γράφουν τα αρχεία.
- **Ο επισκέπτης ζητάει το μήνυμα**: κουμπί στη σελίδα κινητού που ανοίγει WhatsApp προς τη reception με έτοιμο κείμενο
  (variable `VITE_RECEPTION_WHATSAPP`, διεθνής μορφή χωρίς +). Τα στοιχεία επαφής μένουν στο ξενοδοχείο, όχι σε εμάς.
- Variable `VITE_GUEST_URL`: ο σύνδεσμος της σελίδας επισκέπτη που μπαίνει στα μηνύματα και στο QR.

## Φωτογραφίες σημείων

Μία φωτογραφία ανά σημείο από το Wikimedia Commons, μόνο με άδεια ελεύθερης χρήσης (CC BY, CC BY-SA, CC0, public domain) και
με αναφορά δημιουργού πάνω στη φωτογραφία. Το Action «Spot photos» (`.github/workflows/photos.yml`, χειροκίνητο) ψάχνει με τους
όρους του `src/data/photo-queries.ts`, φιλτράρει άδεια/μέγεθος/περιοχή (`src/engine/photos.ts`), κατεβάζει αντίγραφο 1200 px
στο `public/photos/` και γράφει τα στοιχεία στο `src/data/photos.json`. Για δικές σας φωτογραφίες: αντικαταστήστε το αρχείο,
διορθώστε author/license και βάλτε `"locked": true` ώστε να μην αλλάξει ποτέ αυτόματα.

## Εβδομαδιαία αναφορά ιδιοκτήτη

Κάθε Δευτέρα (`.github/workflows/weekly.yml`, `scripts/weekly-report.ts`): ανοίγματα σελίδας και συσκευές, γλώσσες και προφίλ,
ψήφοι 👍/👎 με τα συχνότερα παράπονα, ποια μέρη προτείναμε συχνότερα, μέρες Plan B, εγγεγραμμένοι στις ειδοποιήσεις, και η ακρίβεια
των τελευταίων 30 ημερών. Γράφεται στο `public/data/weekly.json` (πάνελ στην καρτέλα «Μέθοδος»), αρχειοθετείται στο `data/reports/`
και στέλνεται με email στο `OWNER_EMAIL` (ή `RECEPTION_EMAIL`) όταν υπάρχει SMTP.

## Φιλοξενία (GitHub Pages)

Το `.github/workflows/pages.yml` χτίζει και δημοσιεύει τις τρεις σελίδες στο <https://firmusagency.github.io/weather-mood/>
σε κάθε αλλαγή κώδικα και μετά από κάθε Action δεδομένων, ώστε η ζωντανή σελίδα να έχει πάντα το τελευταίο snapshot.
Μία φορά: Settings → Pages → Source: **GitHub Actions**. Σελίδα επισκέπτη: `/guest.html`, ακρίβειας: `/accuracy.html`.
Δικό μας domain αργότερα: Settings → Pages → Custom domain και variables `VITE_GUEST_URL`, `VITE_DASHBOARD_URL`.

## Εντολές

```bash
npm install
npm run dev            # εφαρμογή σε localhost
npm test               # σενάρια (δυτικός 4 Bf, μελτέμι, ζέστη, βροχή, προφίλ)
npm run report -- 2026-10-18 family chania   # αναφορά κειμένου από το τελευταίο snapshot
npm run demo:page      # dashboard ως ένα αρχείο HTML με ενσωματωμένα δεδομένα
npm run demo:guest     # οθόνες επισκέπτη ως ένα αρχείο HTML (VITE_GUEST_URL=... για το QR)
npm run demo:accuracy  # σελίδα ακρίβειας ως ένα αρχείο HTML (VITE_CONTACT_EMAIL, VITE_DASHBOARD_URL για τα κουμπιά)
npm run snapshot:fetch # λήψη νέων δεδομένων (χρειάζεται πρόσβαση στο open-meteo.com)
npm run evening        # βραδινό μήνυμα για αύριο από το τελευταίο snapshot (VITE_GUEST_URL=... για τον σύνδεσμο)
npm run morning-check  # σύγκριση σημερινής πρόγνωσης με το βραδινό μήνυμα → plan-b.json
npm run photos -- falasarna balos   # (ξανα)επιλογή φωτογραφίας για σημεία· χωρίς ορίσματα: μόνο όσα δεν έχουν
npm run feedback:export # εξαγωγή ψήφων από τη βάση (SUPABASE_URL, SUPABASE_SERVICE_KEY) ή -- --from-file rows.json
npm run weekly         # εβδομαδιαία αναφορά ιδιοκτήτη για την τελευταία πλήρη εβδομάδα (ή -- 2026-10-19)
```

## Δεδομένα και αυτοματισμός

- Το GitHub Action `.github/workflows/snapshot.yml` κατεβάζει δεδομένα κάθε 6 ώρες στο `public/data/snapshot-latest.json`
  (3 πλήρεις μέρες για όλα τα σημεία + 7ήμερη πρόγνωση στα σημεία αναφοράς για το πλάνο διαμονής).
  Κρατάει επίσης ένα αρχείο ανά ημέρα στο `data/archive/`, ώστε αργότερα να συγκρίνουμε τις προγνώσεις με την πραγματικότητα.
- Η εφαρμογή μπορεί να φέρει και ζωντανά δεδομένα απευθείας από τον browser (κουμπί «Ζωντανή ανανέωση»).
- Το Action `.github/workflows/verify.yml` τρέχει κάθε πρωί: συγκρίνει την πρόγνωση της προηγούμενης μέρας με τις μετρήσεις
  του σταθμού του αεροδρομίου Χανίων (LGSA, METAR, ωριαία) και με τους 4 σταθμούς του Εθνικού Αστεροσκοπείου στη δυτική/νότια ακτή
  (Φαλάσαρνα, Ελαφονήσι, Παλαιόχωρα, Κίσσαμος· ημερήσια αρχεία `penteli.meteo.gr/stations/<σταθμός>/NOAAMO.TXT`, `src/engine/noa.ts`).
  Ξανατρέχει επίσης την πρόταση με τον άνεμο που μετρήθηκε (`src/engine/recheck.ts`): «άντεξε η πρόταση;» για τα σημεία της βόρειας ακτής,
  και για τα δυτικά/νότια «έπεσε η μεγάλη ριπή της μέρας μέσα στο παράθυρο που δώσαμε;». Αποτελέσματα: `data/verification/`,
  `public/data/verification.json`, καρτέλα «Μέθοδος & πηγές» και `accuracy.html`. Χειροκίνητα: `npm run verify -- 2026-10-18`
  (`--no-metar`, `--no-noa`, `--noa-dir <φάκελος>` για δοκιμές χωρίς δίκτυο).
- Το Open-Meteo είναι δωρεάν **μόνο για μη εμπορική χρήση**. Για πελάτες χρειάζεται συνδρομή API:
  ορίστε το secret `OPEN_METEO_API_KEY` στο repo.
