# Guest privacy: what the app does with data, what changed, what is still open (2026-11-13)

Written while preparing the privacy note that guests can open from the foot of the page. The note has to be true, so
the first step was an inventory of what the pages store, send and load. Three things were fixed on the way.

## Inventory

| What | Where | Why | How long |
| --- | --- | --- | --- |
| Language, "who is travelling", property, departure date (if given), suggestions shown in the last 7 days, notification flags | the guest's browser (`localStorage`, keys `wm:*`) | the page remembers its settings; "did you go, how was it?" | until the guest clears the site data |
| A random per-browser code (`wm:cid`) | the browser; sent with the three items below | one vote per place and day; counting devices; knowing a subscriber is still here | as below |
| Page open: property, view, language, profile, plan date, time, code | Supabase `visits` (Frankfurt, EU) | weekly usage report for the property | **90 days**, then deleted (`wm-visits-cleanup`) |
| Vote: place, day, up/down, reason, optional comment, party size, profile, language, code | Supabase `feedback`; exported nightly **without the code** to `data/feedback/rows.jsonl` and the dashboard | correcting the forecasts (the data nobody else has) | kept; no name attached |
| Notification subscription: browser push address and keys, property, language, profile, code | Supabase `push_subscriptions` | sending the evening message and Plan B | until "Stop notifications", a dead address, or **10 days without a page open** |
| IP address | seen by GitHub Pages (hosting) and Supabase (database calls) as with any website | delivery | their own logs; we do not store it |

No account, no name, no e-mail, no phone number, no location, no advertising or tracking cookies.

## Fixed on the way

1. **Fonts came from Google Fonts** on all three pages, which gave Google the IP address of every guest who opened the
   page (the transfer over which a Munich court awarded a visitor damages in 2022). They are now served from our own site (`src/fonts.css`).
   Verified in a browser: the live pages contact our own host and the database, nothing else.
2. **Notifications never ended.** A guest who turned them on kept getting "tomorrow in Chania" at home until they found
   the stop link. Subscriptions now lapse after 10 days without a page open; the last two messages say so; a guest who is
   still here, or comes back, is registered again silently when they open the page.
3. **Comments would be published as typed.** The repository and the site are public, and the nightly export writes
   comments to both. E-mail addresses, links and phone numbers are now blanked before they leave the database, and the
   field asks for no personal details. (No real comment had been collected yet.)

Also added: page opens are deleted after 90 days (they were kept forever).

## Open, for the owner

- **Who is responsible.** The note says "offered by <property> with the Weather Mood service". It needs the legal name of
  the company behind Weather Mood and an e-mail address for data questions: set `VITE_PRIVACY_OPERATOR` and
  `VITE_PRIVACY_CONTACT` as repository variables (GitHub → Settings → Secrets and variables → Actions → Variables;
  the deploy already reads them), or `privacyContact` per property.
  Until then the note points to the reception.
- **Contract with each property.** Under the GDPR the hotel is the controller for its guests and Weather Mood processes
  data on its behalf: the subscription agreement needs a short data-processing clause. Supabase offers its own DPA from
  the dashboard; accept it on the organisation.
- **A lawyer's reading before the first paying customer.** The text is accurate about what the code does, but it is not
  legal advice. Two points to ask about: (a) the random code stored in the browser is also used to count devices, which
  some authorities treat as needing consent; if so, the page-open count can switch to a code that changes every day (the
  weekly "devices" figure then becomes device-days); (b) whether votes should lose the code after some months.
- **When the custom domain replaces GitHub Pages**, update the "who else is involved" lines in `src/guest/privacy.ts`.
